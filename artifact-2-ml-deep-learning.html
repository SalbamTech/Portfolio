AIML-500 · Artifact 02 · Technical Case Analysis

Machine Learning vs. Deep Learning

Two classification problems, two very different data environments. This case study explains why responsible model selection begins with fit, not novelty.

Model selection Bayesian classification Convolutional neural networks Human oversight

Project Overview

The question behind the artifact

When should a team use traditional machine learning, and when does a problem justify deep learning? I examined email spam detection and diabetic-retinopathy screening to compare the methods across data type, feature extraction, computing cost, explainability, operational risk, and human accountability.

Traditional Machine Learning

Best suited to problems where useful signals can be represented directly and decisions need to remain understandable.

  • Uses engineered or exposed features
  • Works with moderate labeled datasets
  • Requires less computing infrastructure
  • Supports easier investigation and adjustment

Deep Learning

Best suited to high-dimensional, unstructured data where important patterns are difficult to define manually.

  • Learns features from raw images
  • Benefits from large expert-labeled datasets
  • Captures complex spatial relationships
  • Requires stronger validation and monitoring

Case 01

Email spam detection

Why traditional ML fits

Apache SpamAssassin combines understandable message tests with Bayesian filtering. Its learning tool uses messages labeled as spam or legitimate email to identify statistically useful words and tokens. Email also provides direct signals such as links, sender information, message length, header irregularities, and suspicious phrases.

This approach fits an organization running its own mail infrastructure because it can operate on modest hardware, learn from user corrections, and give administrators understandable evidence when a legitimate message is blocked.

Why deep learning is less suitable here

A deep language model could detect sophisticated wording patterns, but it would require more data, computing resources, deployment support, and drift monitoring. For this operating environment, the added complexity may not produce enough value to justify the cost and reduced explainability.

Selected Approach

Bayesian filtering

Traditional machine learning supported by explicit rules and user feedback.

Decision Priority

Transparency, efficiency, local control, and rapid correction of false positives.

Case 02

Diabetic-retinopathy image recognition

Why deep learning fits

A retinal photograph contains millions of pixels and subtle disease indicators that vary in position, size, contrast, and appearance. A convolutional neural network can learn a hierarchy of edges, textures, shapes, and clinically meaningful patterns directly from expert-labeled images.

The original development study used 128,175 retinal images. A later postdeployment study of the automated retinal disease assessment system reported that more than 600,000 patients had been screened across Tamil Nadu, demonstrating that the model moved beyond laboratory validation into a real clinical workflow.

Why traditional ML is less suitable here

A conventional classifier would depend on specialists and engineers manually converting photographs into lesion counts, vessel measurements, color statistics, or texture features. That process can miss subtle pixel relationships and may become fragile when camera conditions or patient populations change.

Selected Approach

Deep CNN

Image recognition trained on a large collection of expert-graded retinal photographs.

Postdeployment Evidence

97.0%

Sensitivity reported for severe nonproliferative or proliferative diabetic retinopathy.

96.4%

Specificity reported for the same severe disease category.

Human oversight remains essential. The model supports screening, but positive, uncertain, and ungradable cases still require qualified clinical review. Performance must be monitored across patient groups, camera conditions, and deployment sites.

Decision Framework

How I evaluated model fit

Data

  • Structured or unstructured?
  • How much labeled data exists?
  • Can useful features be defined?

Operations

  • What infrastructure is available?
  • How quickly must the model run?
  • Who will maintain it?

Responsibility

  • What is the cost of an error?
  • How important is explanation?
  • When must a person intervene?
